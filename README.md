# MY GYM BOOK

Цель проекта — создать удобное веб-приложение для ведения дневника тренировок с возможностью анализа прогресса.
## Основные задачи:
- предоставить пользователям инструмент для регистрации входа пользователей.
- отслеживание  тренировок с помощью календарь, 
- аналитика для отслеживания прогресса,
- таймер для контроля времени тренировки,
- административную панель для управления пользователями.
не авторизованным пользователям доступна главная страница с описанием функционала и таймером.

Важная особенность таймера - запускается в реальном времени, помогая пользователю контролировать продолжительность занятия без необходимости использовать сторонние приложения.
Еще одна ключевая функция — данные тренировки автоматически сохраняются в sessionStorage браузера. Это означает, что если пользователь начал создавать тренировку, но забыл зарегистрироваться или войти, все введенные данные не потеряются. После входа в аккаунт тренировку можно будет сохранить.

## Технический стек проекта:
* Frontend: React с TypeScript, Redux для управления состоянием, Tailwind CSS для стилизации.
* Backend: Node.js с Express, MongoDB в качестве базы данных.
* Деплой: Docker-контейнеризация, облачный сервер Ubuntu с Nginx. (подписка закончилась)

### Кто будет основным пользователем?
Новички, любители и спортсмены, которым важна статистика и аналитика прогресса своих тренировок.

### Почему решили выбрать именно этот проект?
Это ежедневная задача: трекинг прогресса нужен каждому, кто занимается спортом. Интересно совместить таймер с созданием тренировок и аналитикой.

### Чем будет интересен проект для ЦА?
Быстрый старт тренировки через таймер с созданием записи плана тренировки. Визуальный календарь, где видно частоту тренировок, и аналитика за месяц. Гибкая система тегов (части тела, типы нагрузок) для детального учета.

### Какие функции будет выполнять приложение?
- Разделение прав user/admin.
- Запуск таймера тренировки и создание записи на его основе. 
- CRUD операции для тренировок. 
- Администрирование (управление пользователями и тегами тренировок). 
- Отображение статистики за месяц в календаре (количество тренировок, динамика).

### Основные страницы:
1. Главная страница '/';
2. Страница авторизации '/login';
3. Страница регистрации '/register';
4. Страница создания новой тренировки '/workout';
5. Страница информации тренировок авторизованного пользователя + аналитика '/workouts';
6. Страница тренировки '/workouts/:id' (права авторизованного пользователя);
7. Страница со списком пользователей '/users';
8. Страница с ошибкой 404 '*



# ЗАДАЧИ

## Frontend-часть проекта:

### Создать списки элементов
(в проекте должен быть выведен минимум 1 список элементов (в будущем будет получен от сервера через GET-запрос)).
1. Список данных пользователей (страница администратора): логин, дата регистрации, роль.
2. Список видов тренировок (страница создания/редактирования тренировки).
3. Список дат за месяц в виде календаря с отображением активных дат (страница тренировки).
4. Список тренировок авторизованного пользователя за выбранную дату (страница тренировки - модальное окно).

### Создать форму для отправки данных на сервер
1. Форма авторизации;
2. Форма регистрации;
3. Форма создания и редактирования тренировки;

### Реализовать кастомные хуки
1. useFetch - выполнения асинхронных запросов к API.
Состояния: загрузка и ошибки.
Централизованная обработка ошибок с выводом сообщений в зависимости от кода ответа.
Защита от утечек памяти: useRef и функции очистки в useEffect при размонтировании компонента. предотвращает обновление состояния, если компонент размонтирован (пользователь ушел со страницы до завершения запроса).

2. useOpen - управление состоянием видимости модальных окон, боковой панели.
Возвращает объект с текущим состоянием и двумя обработчиками для его изменения.

### Создать приватные страницы
(доступная только авторизованным пользователям или пользователям только с определенными правами (Private Route))
1. Права администратора: страница со списком пользователей '/users'
2. Права авторизированного пользователя:
2.1. Страница создания новой тренировки '/workout',
2.2. Страница тренировок авторизованного пользователя '/workouts';
2.3. Страница одной тренировки '/workouts/:id'

### Реализовать редактирование/удаление элементов
(предоставить возможность пользователям редактировать элементы)
1. Администратор имеет право редактировать/удалять роль пользователя.
2. Авторизованный пользователь имеет право редактировать/удалять свою тренировку.

### Использовать библиотеку для управления состоянием Redux
Глобальное состояние (RootState) состоит из следующих слайсов:
- authorizedUser — хранится объект текущего пользователя для отображения интерфейса в зависимости от роли.
- users — список всех пользователей для администратора (удаление, редактирование),
- workout - данные о тренировке (редактирование, удаление),
- workouts — список тренировок за период(месяц).
Для асинхронных запросов к бэкенду использую middleware Redux Thunk. Компоненты читают данные через useSelector, а действия инициируют через useDispatch.
